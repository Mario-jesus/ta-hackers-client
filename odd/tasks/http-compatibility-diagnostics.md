# HTTP compatibility diagnostics

## Objective

Make the legacy HTTP client observable and correct for compressed responses, then compare bounded read-only backend responses without assuming that the current game protocol matches this repository.

## Problem and evidence

- Clean Ruby 3.3.12 / Bundler 2.6.9 runs the existing 669 offline examples with no failures.
- Loopback responses show gzip remains compressed, empty non-200 responses raise a parser error, and HTTP status is discarded.
- The supplied 1.224, 1.227 and 1.229 APK metadata contains the same host/path and public salt strings. String presence does not prove an unchanged active algorithm. *(Previous-stage evidence — the active-algorithm gap was later resolved, see the 2026-10-04 items below.)*
- *(Previous-stage evidence, superseded)* The initially supplied 1.227 and 1.229 APK splits contained metadata but no native libraries, so at that stage the active `app_version` and hashing implementation remained unverified. Labeled historical, not a current unknown.
- New stage 2026-10-04: later-supplied full XAPK/APK packages include arm64 native libraries. A bounded, read-only static IL2CPP analysis (*independent of this repo*) **confirmed identically in 1.227 and 1.229**: wire `app_version` = `Application.version` with dots removed, `TrimStart('0')`, `Int32.Parse` (1227→`1227`, 1229→`1229`; versionCode `122903` is not referenced); host/path `https://hackers-1.appspot.com/req.php`; salt `ZqQxXFFy` inserted at offset 10 after `Substring(29)` of the canonical URL; MD5 over UTF8 → `ToBase64String(h,2,6)` (bytes[2..7]) → url-map `=→. +→- /→_`; `&cmd_id=` appended after the hash; `&app_version=`/`&session_id=` insertion order in `NetRequest_url`; login response `fields[3]`→sessionId, `[4]`→cpState.
- Native auth difference (confirmed, both versions): `auth_id_password` is a valueless flag with **no `=`**, while the Ruby client sends `auth_id_password=` (empty value with `=`). Same parameter order otherwise (`auth_id_password`, `id_player`, `password`, `app_version`).
- Limits preserved: server-side validation semantics remain unknown (the prior live HTTP 200 with the old Ruby formula does not prove validation); per-command parameter lists for other commands are not enumerated; native login concatenates credentials RAW with no escaping (do **not** copy this — this repo keeps `URI.encode_www_form` for values); each client hashes exactly the string it sends, so the space (`%20` vs `+`) encoding nuance is a documented difference, not proof of server-auth failure. Full report copied verbatim to `docs/ta-hackers-native-protocol-analysis.md` (source sha256 `ce77ef26c0857841c926de3769af5f58369067a6d2cbe9c2e1cce1bc571a74ec`, 165 lines, byte-identical).

## Acceptance criteria

- Gzip and identity responses are processed correctly without double decompression.
- Malformed gzip produces a useful transport error instead of silent corrupted parsing.
- Empty or HTML non-200 responses retain status and do not leak parser exceptions.
- Known game error mapping continues working and exposes HTTP status.
- Error evidence is bounded, validly encoded, and avoids reflecting arbitrary response bodies or credential URLs in ordinary error messages.
- Existing offline tests pass unchanged; no test contacts the game server.
- Backend outcomes are classified as observations, not proof of the entire current protocol.
