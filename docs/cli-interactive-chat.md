# Exception-safe interactive chat ownership

The T0a lifecycle change removes a failed or stopped poller from the local room registry and closes only the room it still owns. It does **not** fix interactive terminal redraw: the installed SDK can still raise `NoMethodError` when `Readline` resolves to Reline without `refresh_line`.

## Lifecycle contract

| Event | Local outcome |
|-------|---------------|
| Request error | Stop polling, report the exception class only, and clean up ownership. |
| Unexpected output or logging error | Clean up in `ensure`; the worker reports only its class and retains the original exception for `Thread#value`/`join`. Disable automatic raw thread reports on that worker only. |
| Error reporting itself fails | Cleanup still runs; the reporting exception propagates. |
| Normal nil response or thread kill | Remove the registry entry and close the locally owned room. |
| Explicit close followed by reopen | Detach and close locally before killing the old worker; its delayed cleanup cannot delete or close the new owner's room. |
| Immediate worker completion | A queue start barrier prevents polling until its exact Thread object is registered. |

A mutex serializes registry ownership and the dataset's local `open`/`close` operations. These operations do not issue requests. Polling, output, thread kill and thread join never occur while holding that mutex. Cleanup compares the registered owner with `Thread.current`, not merely the room number. No worker restart or request retry is introduced; the default five-second interval and one-second floor are unchanged.

## T0b1 standalone callback prototype (local, not injected)

A standalone C module (`ext/cli_readline_callback/`) binds the documented public GNU Readline 8.3 callback APIs without loading `readline-ext` or touching SDK private state. One UI owner uses `CliReadlineCallback.install/read_char/emit_message/remove` (plus `session`, `buffer`, `point`, `version`): C-owned callback data (line/EOF records, cancellation pipe), Ruby objects created only under the GVL, native blocking reads released via `rb_thread_call_without_gvl` with a signal-safe unblock, and ownership/GV/GC/exactly-once-free/EOF/exception-interrupt cleanup enforced in C. Producers must not write the terminal while editing; `emit_message` clears the visible line, prints, and relies on the owner's single `redisplay`.

Build locally with `ruby scripts/build_cli_readline_callback.rb` through the project toolchain launcher; artifacts stay under ignored `.bundle/native-readline-callback/` (extconf finds `rl_callback_handler_install` in `-lreadline`; GNU 8.3 version is asserted at install). `spec/cli_readline_callback_spec.rb` covers the contract, lifecycle and a real-PTY display gate; see `odd/tasks/cli-authenticated-chat-tests.md` for observed counts. The historical 5-examples/4-failures run before any edit is a harness RED, not behavioral test-first proof for the native module: the original native product RED is unavailable because the resumed writer inherited the already-written partial C source and checked it as-is (no native code was deleted or reverted to fabricate one). All four failures were fixture/model defects — the unstable `IO::ConsoleMode#==` restore comparison and the screen model missing ECMA-48 ICH/DCH/ECH — and the native module needed no change for them. An independent verifier reproduced focused 5/0, the 124/0 focused CLI/API set, the 1001/0 full suite and the true midframe barrier (4096 of 180316 output bytes drained with the frame still owned), then found one latent screen-model defect: ECH truncated the untouched tail beyond the erased span; the real PTY stream never emits it, so the gate itself stayed valid. A dedicated pure-model regression was added, observed RED (destroyed tail, collapsed row width), and the model corrected; unknown ANSI remains fatal, and ICH/DCH/ECH clipping, unchanged width/cursor and preserved tails are now pinned. GREEN is 11/0 complete callback spec (5 PTY gate + 6 model) and the full suite reported in the feature tracker; helpers pass 24+10 offline self-tests. Prototype limitation: `emit_message` holds the GVL while its `fputs` output may block on PTY capacity — T0b2 must evaluate edit responsiveness/streaming separately; no native change or integration is authorized at prototype scope.

Not injected into the production shell. Still unproved: colored/wide-Unicode/grapheme prompts, resize, input history, post-unwind edit snapshots, and real SDK/Reline parity (T0b2 must map and prove that separately); PTY display assertions above were, and remain, the gate for any integration claim. ## T0b2a native compatibility extension (historical record; unit closed at parent commit `f81e1899` with native review/ACK receipts)

The module gained narrowly scoped public APIs for the planned adapter: `wake` (producer thread, distinct from the SIGINT cancellation pipe), `completion=` plus owner-supplied callbacks invoked through the documented public `rl_attempted_completion_function`, `add_history` with public up/down navigation, public `resize` (`rl_resize_terminal` + redisplay), and UTF-8/color prompts through the public `RL_PROMPT_START_IGNORE`/`END` markers. Existing `install/session/read_char/emit_message/remove/buffer/point/version` contracts and owner/rejection/EOF/SIGINT/exception/GC/free semantics are unchanged.

Completion discipline: the callback runs only inside a without-GVL `native_read` round (guarded by `in_native_read`); Ruby work re-acquires the GVL with `rb_thread_call_with_gvl` and every Ruby call is wrapped so no exception unwinds GNU frames — the captured exception is re-raised by the owner under the GVL through the existing `read_rescue` cleanup. C-owned match strings are freed even on partial failure; GNU frees them on success. Registry layout per the GNU manual convention: with several candidates slot 0 carries the maximal common substring of all matches (computed byte-wise then backed off to a UTF-8 boundary so a multibyte character is never split) and the full list follows; with exactly one candidate the registry holds only that unique match. With an installed completion callback, a nil/empty/unmatched result never falls back to default filename completion: the callback entry sets the documented public `rl_attempted_completion_over` and the saved old value is restored at cleanup and on a mid-session clear; without an installed callback GNU's documented default completion applies. Malformed partial lists (non-String entries or NUL bytes) raise owner TypeError/ArgumentError with full cleanup and the session can be reopened; the registry-free rescue path exists, and no allocation-fault-injection proof is claimed. Writer-observed outcome, unconfirmed beyond this writer run (explicit note, not a verified Ruby-version fact): on Ruby 3.3 `rb_protect` returned `Qnil` with a nonzero state (6) and `rb_errinfo()` also read `Qnil` inside the same GVL callback; capture therefore used the documented equivalent `rb_rescue2(..., rb_eException)`, which passed the exact exception object. `rl_completion_suppress_append` (the documented application-completion switch) prevents the appended character. History: `using_history()` is called at install and again after each `add_history` — observation showed GNU's navigation anchor loses the newest entry otherwise (arrow recall inserted nothing until re-anchored). `rl_point` counts bytes: a typed accented sequence yields point 5 while the visible cursor advances column by column.

Writer-reported GREEN (historical; test-first RED for absent APIs was recorded before the C change and the ×3 stability was a writer stability note, never independent proof): callback spec 18 examples/1 failure (the single wake example RED) stable ×3, full suite 1014/1 with the same single failure, focused CLI/API 119/0, helpers 24+10 self-tests, three Ruby syntax checks. PTY proofs passed with the real terminal: completion prefix/full-buffer + GC + owner + exception cleanup + inactive rejection; history add with blanks and immediate duplicates plus up/down navigation recall; UTF-8/color prompt marker layout with correct visible columns and exact submission (`▸` and `á` at width 1 only — the screen model stays fatal for untested glyphs); resize through a real PTY winsize change with reflowed prompt/input and cursor position.

## T0b2a pre-freeze completion fix (parent-authorized within authorized T0b2a; unit closed)

An independent verifier proved the ambiguous-completion contract wrong (proc `['help','hello']` with typed `he`+TAB inserted `help` at point 4 instead of the maximal common substring `hel` at point 3) and a static contract gap (an installed proc returning nil/`[]` fell back to filename completion because `rl_attempted_completion_over` was never set). The fix: slot 0 is now the maximal common substring (byte compare backed off to a UTF-8 boundary; single-candidate lists keep the proven unique layout), and a callback entry sets the documented public `rl_attempted_completion_over` (saved at install, restored at cleanup and on a mid-session clear; the no-proc path keeps GNU's documented default completion).
